# 2026-10-04 oci 모듈

- 범위: OCI runtime-spec 1.2 값 타입과 JSON(파싱/쓰기/검증, runc 기본 설정), OCI·Docker seccomp 변환, 상태
  저장(`state.json`, exec.fifo, 잠금), `CRuntime`(create/start/state/kill/delete/exec/ps/pause/resume/update/
  list/stats), 훅, 콘솔 소켓, `sbox`/`sboxrun` CLI(runc 명령과 출력 형식, logrus text/json 로그).
- 참조: 이 기계의 runc 1.3.6을 직접 돌려 `spec`/`spec --rootless` 출력, `state`/`list`/`ps` 형식, 오류 문자열과
  종료 코드, `--log` 사용 시의 출력 방식을 확인하고 테스트 픽스처로 넣음(`tests/data/runc-*.json`). Docker 기본
  seccomp 프로필은 moby/profiles 저장소에서 받아 넣음.
- box 변경(가산적): `SLaunchSpec::orphanPayload`. pid 네임스페이스에 들어가는 early fork의 바깥 프로세스가
  reaper로 남으면 shim이 pid 파일의 pid(페이로드)를 거둘 수 없어서, 페이로드 pid를 보고하고 바로 끝나는
  선택지를 추가함(runc의 exec와 같은 프로세스 모양). box 테스트 하나 추가, docs/box.md 갱신.
- 처음에는 상태 잠금을 디렉터리 flock으로 했는데, start gate에서 기다리는 init이 런타임의 디스크립터 사본을
  exec 전까지 갖고 있어 flock(열린 파일 설명 단위)이 init에 남아 `start`가 30초 대기 후 실패함. 상속되지 않는
  POSIX 레코드 잠금(`.lock` 파일)과 프로세스 내부 목록으로 바꿈.
- create에서 프로그램 존재 확인: init이 gate에서 기다리는 동안 `/proc/<pid>/root`를 루트로 `openat2
  (RESOLVE_IN_ROOT)` PATH 검색. runc처럼 `exec: "x": executable file not found in $PATH`를 create가 돌려줌
  (Docker가 이 문자열을 그대로 보여 주고 127로 끝냄).
- v1/hybrid 호스트의 `/sys/fs/cgroup` cgroup 마운트는 v1 계층 전체를 새로 마운트하면 EBUSY이므로 runc처럼
  tmpfs + 컨테이너 cgroup 디렉터리 bind로 바꿈.
- 테스트 중 GCC 13 ICE(co_await 안의 중괄호 초기화 목록)를 한 번 만나 지역 변수로 바꿈. 테스트 코드의 임시
  문자열에 대한 string_view(로그 줄 검사) 실수를 고침.
- 검증: `ctest -L oci` 6개(+ 선택 1개) 통과. 별도로 이 기계에서 전용 dockerd(29.6.2)를 띄워
  `docker run --runtime=sboxrun`(종료 코드, -t, -d, exec, pause, update, stats, stop, rm, host 네트워크, -u,
  --read-only, -m)과 `ctr run --runc-binary`가 동작함을 확인했고, 같은 시나리오를 `SBOX_TEST_DOCKER=1`
  선택 테스트로 넣음.
- core 변경 없음.
