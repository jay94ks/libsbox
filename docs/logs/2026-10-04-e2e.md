# 2026-10-04 e2e (모듈 간 통합)

- 범위: 병합된 모듈(core, box, oci, archive, http, tls, image, vol, net, vpn/wg)과 CLI를 사용자 흐름대로
  잇는 테스트 모듈 `modules/e2e`, 문서 `docs/e2e.md`, `docs/usage.md`.
- 격리 방법을 먼저 정함: 테스트 프로세스가 정적 초기화에서 사적 마운트 네임스페이스로 옮겨 가므로
  `sbox-image`의 overlay 마운트, 볼륨, netns 고정 bind가 호스트에 남지 않음. 네트워크는 임시 netns를
  "호스트"로 씀. 도구 실행은 fork+exec와 pidfd 대기라 같은 루프의 테스트 레지스트리가 계속 응답함.
- 이미지 픽스처는 테스트 안에서 archive 모듈로 만든 두 레이어(두 번째에 whiteout)와 docker save/레지스트리
  두 형식. busybox가 없어 호스트 프로그램과 ldd 라이브러리, 직접 만든 `e2ehelper`(TCP 서버/클라이언트,
  악성 동작)를 넣음.
- 찾은 문제와 수정
  - README 예제가 컴파일되지 않음(`sandbox.hpp`에 `CEventLoop` 없음) → `sandbox.hpp`가 eventloop 포함.
  - README 예제를 돌리니 SIGPIPE(141)로 죽음: 샌드박스 프로그램이 먼저 끝나면 stdin 파이프 쓰기가
    호출자를 죽임. 악성 프로그램이 감독자를 죽일 수 있는 문제라 core `CStream::send`에서 파이프 쓰기 동안
    SIGPIPE를 막고 그 쓰기가 만든 신호를 `sigtimedwait`로 거둠(-EPIPE). 이미 대기 중이던 SIGPIPE는 남김.
  - `/usr`만 bind하면 merged-/usr 호스트에서 `/lib64/ld-linux...`가 없어 모든 동적 프로그램이 `execve`
    ENOENT → 호스트 `/usr`를 bind한 정책에 `/bin`, `/sbin`, `/lib*`를 `/usr` 안에서 읽기 전용 bind.
  - 남은 것: README 예제의 `cwd`(main.py를 `/`에서 찾음)와 `/etc` 미마운트(`/usr/bin/python3 ->
    /etc/alternatives/python3`). 문서 문제라 README를 고칠 문안을 `docs/e2e.md`에 적고 `e2e_readme`는 실패로
    둠.
- GCC 13이 co_await 식 안의 문자열 중괄호 목록에서 ICE → 인자를 가변 템플릿 `Args(...)`로 만듦.
- 임시 "호스트" netns는 `lo`가 꺼져 있어 127.0.0.1 포트 매핑이 ENETUNREACH였음(라이브러리 문제 아님) →
  테스트가 `BringUpLoopback`.
