# 2026-10-04 vpn: IPsec(XFRM)와 IKEv2 응답자

브랜치 `claude/sbox-vpn-ipsec`. 설계의 최종 상태는 [../vpn-ipsec.md](../vpn-ipsec.md)에 있습니다.

## 진행

1. libcertpp 헤더와 tls 모듈의 사용법을 읽고 공용 암호 계층(`ikecrypto`)부터 만들었습니다. AES-CBC는
   certpp의 `ESYMPAD_NONE`(IKEv2를 위해 들어간 옵션)으로, AES-GCM/ChaCha20-Poly1305는 AEAD 클래스로,
   MODP DH는 `CBigNum`/`CMontgomery`로 구현했습니다. MODP-2048 소수는 OpenSSL 3의 `modp_2048`과 비교했고,
   MODP-1024(OpenSSL 3에 없음)는 Python으로 안전 소수 판정과 비트 길이를 확인했습니다.
2. 개발 머신 커널을 먼저 조사했습니다: `NETLINK_XFRM`은 있지만 esp4, xfrm 인터페이스, gcm/authenc가 없어
   ESP SA는 `-EPROTONOSUPPORT`, AEAD는 `-ENOSYS`, `xfrm` 링크는 `-EOPNOTSUPP`. raw ESP 소켓과 TUN은
   동작합니다. 그래서 브리프에서 "시간이 되면"이던 사용자 공간 ESP를 실제 기본 경로로 구현했고, 커널
   경로는 탐지 후 자동 선택하게 했습니다.
3. 테스트 벡터: RFC 7296에는 벡터가 없어 prf+, SKEYSEED/KEYMAT 구조, X25519/MODP 공유 비밀, 세 가지 봉인
   변환의 기댓값을 Python `hmac`/`hashlib`과 `cryptography`(OpenSSL)로 따로 계산해 테스트에 넣었습니다.
   MS-CHAPv2는 RFC 2759 9.2, 키 유도는 RFC 3079 3.5.3(이 벡터의 SendStartKey128은 서버 송신 키, 즉 Magic3
   라는 점을 테스트를 고치며 확인)을 썼습니다. EAP-MSCHAPv2 MSK는 hostapd/[MS-CHAP] 3.1.5.1과 같은
   "피어 송신 키 | 피어 수신 키"이며 64바이트로 0을 채웠습니다(HMAC 키 패딩 때문에 결과는 32바이트 MSK와
   같음).
4. 응답자와 같은 라이브러리에 최소 개시자(`CIkeInitiator`)를 만들어 루프백에서 모든 인증 방식, 재키잉,
   DPD, DELETE, 단편화, COOKIE, INVALID_KE, 강제 NAT-T를 왕복 시험했습니다. 개시자와 응답자가 같은 오해를
   공유할 위험은 위 독립 벡터와 OpenSSL 교차 검증(인증서), RFC 대조로 줄였습니다.
5. 두 netns와 veth로 사용자 공간 ESP 위에서 실제 UDP 트래픽(raw ESP, UDP 4500 캡슐화, 재키잉 후)을
   주고받는 테스트를 만들었습니다.
6. ASan+UBSan 빌드(`-DSBOX_SANITIZER=address,undefined`)로 vpn 테스트를 모두 돌려 오류가 없음을
   확인했습니다(퍼징 포함).

## 결정과 이유

- **제안 선택**: 처음에는 상대 제안 순서를 따랐는데, Windows 기본 제안의 첫 항목이 3DES라 3DES가
  골라졌습니다. 우리 암호화 알고리즘 선호가 모든 제안에 걸쳐 우선하도록 바꿨습니다.
- **직렬 처리 큐**: 데이터 경로 설치가 비동기라, 수신 메시지·타이머·stop을 한 큐에서 차례로 처리해 SA
  상태 경쟁을 없앴습니다(창 크기 1이라 처리량 문제 없음).
- **재키잉 시 정책 유지**: 정책은 reqid 단위로 설치하고 CHILD 재키잉은 같은 reqid로 SA만 바꿉니다.
- **IKE_AUTH의 ESP 제안 DH**: IKE_AUTH에서는 무시하고, CREATE_CHILD_SA는 KE가 있을 때만 PFS 그룹을
  요구합니다.
- **소유자 범위 정리**: reqid 기본 범위 `0x5b000000`-`0x5bffffff`로 우리 XFRM 항목만 지웁니다.
- 공용 부분(`CIkeSocket`, `ikecrypto`, `CXfrm`, 데이터 경로, MS-CHAPv2)은 L2TP/IPsec(IKEv1) 작업이 그대로
  쓰도록 IKEv2 전용 상태를 넣지 않았습니다.
