# 2026-10-04 box 모듈

- 실행 엔진(`SLaunchSpec`/`CProcess`)을 샌드박스 전용이 아닌 범용으로 설계: oci 모듈이 create/start/exec를
  이 위에 만들 수 있도록 네임스페이스 들어가기, 기존 rootfs 디렉터리, 범용 마운트 목록, 가림/읽기 전용 경로,
  FIFO start gate, 콘솔 소켓, `detach()`를 넣음.
- clone3 뒤 자식은 미리 만든 평면 계획만 읽고 시스템 콜만 부름. 오류는 단계 이름과 errno를 담은 고정 크기
  레코드로 close-on-exec 파이프에 보냄.
- 처음에는 bind 소스를 부모가 O_PATH로 열어 넘겼으나, 다른 마운트 네임스페이스의 마운트를 bind하면
  커널이 EINVAL을 돌려줘서 자식이 자기 네임스페이스에서 열도록 바꿈. 이어서 staging 디렉터리(`/tmp`)를
  포함하는 경로를 재귀 bind하면 새 루트가 딸려 들어오는 문제가 있어 `open_tree(OPEN_TREE_CLONE)` +
  `move_mount`로 바꿈. `move_mount`의 대상은 매직 링크 경로가 아니라 `MOVE_MOUNT_T_EMPTY_PATH`와 O_PATH
  디스크립터로 지정해야 함(경로로 주면 링크 자체가 대상이 되어 EINVAL).
- root가 실행할 때 안의 root를 호스트 65534에 매핑하자 tmpfs에 마운트 지점을 만들 때 EOVERFLOW: 커널
  자격 증명(호스트 0)이 새 사용자 네임스페이스에 매핑되지 않았기 때문. 동기화 직후 매핑된 ID로 바꾸고
  capabilities를 다시 올리도록 함.
- uid를 바꾼 비특권 프로세스는 dumpable이 아니라서 부모가 `/proc/<pid>/setgroups`를 쓸 수 없었음. 자식이
  동기화 동안만 dumpable이 되게 함.
- 악성 rootfs의 끊어진 심볼릭 링크(`/escape -> /var`, 대상 없음)를 따라 마운트 대상을 만들 수 있도록
  구성 요소를 직접 걸으며 링크를 루트 기준으로 다시 해석하는 경로 해석기를 씀.
- seccomp BPF: 64개 단위 디스패치 블록 사이를 기본 동작으로 잘못 점프하던 버그를 테스트(인터프리터
  `evaluate`)에서 발견해 고침. 64비트 비교는 연산자 × 경계값 전수 검사로 확인.
- 장치 eBPF 프로그램: 조건 없는 규칙 뒤에 기본 반환을 두면 검증기가 도달 불가 코드로 거절(EINVAL)해서
  생략하도록 함.
- 보고 레코드를 한 번에 여러 개 읽었을 때 종료 레코드 뒤의 `EXIT`를 버리던 경쟁을 병렬 반복 실행으로 찾아
  고침.
- GCC 13은 `co_await` 식 안에서 `std::string` 임시 객체를 만드는 중괄호 초기화 인자에 ICE를 냄(테스트에서
  인자 벡터를 먼저 만들어 우회). 문서의 예제 형태(`{ "/usr/bin/python3", "main.py" }`)는 문제없음.
- 이 기계(hybrid, v2에 컨트롤러 없음, root, CAP_SYS_RESOURCE 없음)에서 box 테스트 4개(케이스 59개)가 통과.
