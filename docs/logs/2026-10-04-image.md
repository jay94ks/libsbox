# 2026-10-04 image 모듈

- 범위: Docker 참조 문법과 정규화, OCI image layout 저장소(blob 검증·원자적 반영·재개, flock, lease,
  db.json), Registry API v2 pull/push(Bearer/Basic, config.json, 미러, insecure, certs.d, 프록시, Range 재개,
  동시 다운로드, 플랫폼 선택, schema 1 거부), 레이어 스냅샷(overlay whiteout, rootless userxattr), overlay/복사
  컨테이너 루트, commit, 이미지 설정 → OCI runtime-spec 번들(Docker 기본 마운트·능력·masked paths·seccomp),
  `docker save`/`docker load`와 OCI 아카이브, GC와 `rmi`, `sbox-image` CLI.
- 저장소는 디렉터리 자체를 OCI image layout으로 둠. index.json 항목은 항상 플랫폼 manifest를 가리키고, 이름은
  `io.containerd.image.name`(전체 참조)과 `org.opencontainers.image.ref.name`(태그)으로 둠. 태그를 옮길 때
  원래 manifest는 dangling으로 남겨 Docker의 `<none>` 이미지와 같게 함.
- 레지스트리: 엔드포인트 URL을 핑 전에 만들면 HTTPS → HTTP 대체가 반영되지 않는 문제가 있어, 요청 경로를
  엔드포인트 기준 상대 경로로 넘기고 핑 뒤에 기준 URL을 붙이도록 고침. 동시 다운로드 코루틴이 같은
  엔드포인트를 동시에 핑하며 스킴을 서로 덮어쓰는 경쟁도 발견해 핑을 한 번만 돌게 함.
- GCC 13의 코루틴 ICE(co_await 식 안의 `std::string` 중괄호 초기화 목록)를 만나 스코프 목록을 함수로 만들도록
  바꿈.
- overlay: 새 마운트 API의 `lowerdir+`(6.8+)를 기본으로, legacy `mount(2)`는 페이지 크기를 넘으면 overlay2처럼
  `<root>/l/` 짧은 링크 + chdir. 처음에는 `snapshots/` 기준 상대 경로만 썼는데 70개 레이어에서 4 KiB를 넘어
  짧은 링크 방식으로 바꿈.
- rootless overlay는 테스트에서 fork한 자식이 사용자·마운트 네임스페이스를 만들고 `userxattr`로 마운트해
  xwhiteout까지 확인(부모는 pidfd + 이벤트 루프로 기다림).
- seccomp: moby 기본 프로필 형식 그대로 모듈에 넣고 dockerd의 변환 규칙(includes/excludes, archMap,
  minKernel)을 구현.
- `docker save`는 Docker 25+ 모양(oci-layout + blobs + index.json + manifest.json + repositories)으로 만들고, load는
  같은 아카이브의 manifest를 재사용해 manifest 다이제스트까지 유지함. 고전 `<id>/layer.tar` 형식도 손으로 만든
  tar로 검증.
- 실제 Docker Hub(HTTPS_PROXY 경유): `SBOX_TEST_NETWORK=1`로 `alpine:latest`(3.85 MB, 약 3초)와
  `busybox:latest`(2.2 MB, 약 2초)를 받아 스냅샷과 펼친 루트 확인. CLI로 pull → bundle → chroot 실행 →
  overlay mount → commit → save/load → rmi → prune까지 수동 확인. 권한 없는 사용자(uid 65534)로도 pull과
  복사 방식 번들 확인.
- 검증: Debug(-Werror) 빌드에서 `ctest -L image` 8개 통과, AddressSanitizer + UndefinedBehaviorSanitizer 빌드에서도
  통과.
- core 변경 없음.
