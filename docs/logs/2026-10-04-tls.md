# 2026-10-04 tls 모듈

- libcertpp 기본 요소 위에 TLS 1.3 클라이언트와 TLS 1.2(ECDHE + AEAD, EMS 필수) 대체 경로, 신뢰 저장소,
  경로 검증을 구현. 공개 진입점은 http 모듈이 쓸 `ConnectTls(transport, options, out)`.
- libcertpp 헤더가 `-Wshadow`에 걸려 `thirdparty/CMakeLists.txt`에서 `certpp`를 SYSTEM 타깃으로 지정.
- 트랜스크립트는 해시 상태 대신 바이트로 보관하고 필요할 때 해시: HRR의 message_hash 대체와
  1.2에서 스위트 결정 후 해시 선택이 단순해짐. 핸드셰이크 메시지는 작아 비용 무시 가능.
- 발급자/주체 대조는 libcertpp의 `CDistinguishedName`(속성 종류별 맵이라 정보 손실)이 아니라 DER에서
  잘라낸 원래 바이트로 함. critical 확장 목록도 libcertpp가 열거 API를 주지 않아 작은 DER 워커로 읽음.
- RFC 8448 원문 사이트는 프록시 정책으로 막혀 있어, 핸드셰이크 바이트는 Botan의
  `tls_13_rfc8448/transcripts.vec`, 중간 값은 mbed TLS 테스트 데이터의 RFC 8448 값으로 확인. 전부 일치.
- 테스트 중 발견: ec_point_formats 파싱 루프가 단락 평가로 무한 루프(악의적 서버로 멈출 수 있었음) → 수정.
  GCC 13이 co_await 식 안의 중괄호 초기화 목록에서 ICE를 내서 테스트 코드는 이름 있는 벡터를 씀.
- 실제 Docker Hub(프록시 경유, 프록시 CA는 `SSL_CERT_FILE`)로 1.3/1.2 모두 접속, `/v2/` 401 확인.
